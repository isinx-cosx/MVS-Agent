# 指南：命令与配置

这一篇是**参考手册**：启动参数、npm 脚本、配置项、环境变量、工具清单。所有条目都对着当前代码核对过。

---

## 启动服务

```powershell
node src/cli/serve.ts [参数]
# 或 npm run serve
```

| 参数 | 作用 |
|---|---|
| `--port <n>` | 监听端口（默认 3080 一类的默认值，见启动输出） |
| `--profile <名字>` | 用命名预设：`ollama` / `llama` / `deepseek` / `fake` |
| `--base-url <url>` | 直接指定端点（压过 profile） |
| `--model <name>` | 指定模型名 |
| `--api-key <key>` | 直接给密钥（会出现在命令历史里，慎用） |
| `--context-window <n>` | 声明上下文窗口（探测失败时的兜底） |
| `--workspace <path>` | 启动时打开的工作区 |
| `--mode <模式>` | 默认权限模式：`read-only` / `workspace-write` / `full-access` |
| `--dev` | 启用内置开发页 `/dev`（不启用时访问会 404，响应体说明原因） |
| `--require-token` / `--no-token` | 强制开启 / 关闭访问令牌 |
| `--app` / `--no-app` | 是否用独立窗口打开界面 |

**令牌**：默认要求。浏览器第一次访问要用 `/?token=…` 带上令牌，之后写 cookie（7 天）。开发阶段本机自用可以 `--no-token` —— 但要知道，关掉之后**同机任何程序**都能直接调 `/command`（它能执行命令、能写文件）。浏览器跨站页面仍被 Host / Origin / Sec-Fetch-Site 三道挡着。

| 脚本 | 用途 |
|---|---|
| `npm run chat` | 裸对话 REPL（**不给工具**，用于验证模型本身） |
| `npm run chat:ollama` / `chat:deepseek` | 同上，带预设 |

| `npm run skills` / `npm run plugins` | 列出、审批、启停 |
| `npm run eval` | 跑评估集 |
| `npm run maintain` | 清理过期状态（会话、快照、作业日志） |
| `npm run sandbox:grant <路径>` | **一次性**授权沙箱（管理员） |
| `npm run sandbox:quota` | 说明为什么 Windows 上做不到按 SID 的磁盘配额 |
| `npm run ads:restore` | 从快照恢复 NTFS 备用数据流 |
| `npm run reveal:code` | 生成可见性代码（让模型临时"看见"被打码的内容） |
| `npm run ui:build` / `ui:build:dev` | 构建界面 |
| `npm run tools:check` | 工具自检 |
| `npm test` / `npm run typecheck` / `npm run ui:typecheck` | 验证 |

## 配置文件

位置：`%USERPROFILE%\.mvs-agent\config.json`（可用 `MVS_HOME` 改整个状态目录）。

```jsonc
{
  "version": 1,
  "model": {
    "baseUrl": "http://127.0.0.1:8080/v1",
    "model": "qwen3.6",
    "apiKeyEnv": "MVS_API_KEY",   // 从环境变量读密钥（优先于明文）
    "apiKey": "****",             // 明文密钥（界面里永远是打码的）
    "contextWindow": 32768
  },
  "defaultMode": "workspace-write",
  "server": { "port": 3080, "requireToken": true },
  "providers": { },               // 多供应商 route（可选）
  "activeProvider": "…"           // 选了哪个 route（可选）
}
```

**没有默认供应商。** 什么都不配时启动会显示「未配置模型」，而不是悄悄连本机 Ollama —— 因为"没配"和"配了 Ollama"在界面上长得一样，那正是最容易被误信的假值。

改配置：

```powershell
node src/cli/config.ts set model.baseUrl http://127.0.0.1:8080/v1
node src/cli/config.ts set model.model qwen3.6
node src/cli/config.ts get model
```

界面「设置 → 模型」改的是同一份文件。坏配置不会让服务起不来：会报警、说明是哪个字段、并**先备份再覆盖**。

## 环境变量

| 变量 | 作用 |
|---|---|
| `MVS_HOME` | 状态目录（默认 `~/.mvs-agent`） |
| `MVS_PROFILE` / `MVS_BASE_URL` / `MVS_MODEL` / `MVS_API_KEY` | 覆盖模型配置 |
| `MVS_PROVIDER_ROUTE` | 指定多供应商里的哪个 route |
| `MVS_SANDBOX` | `off` = 关沙箱；不设 = 开 |
| `MVS_SANDBOX_NET` | `1` = 沙箱内允许网络（会退到受限令牌 + Job，而不是 AppContainer） |
| `MVS_SANDBOX_MAX_PROCESSES` / `_MAX_MEMORY_MB` / `_MAX_WRITE_MB` | 沙箱资源上限 |
| `MVS_ALLOW_NET` | 白名单式放行网络出口，如 `npm,pip`（`1` = 全放） |
| `MVS_RECOVERY_DIR` / `MVS_SESSION_DIR` / `MVS_JOB_DIR` | 恢复层 / 会话 / 作业的存放目录 |
| `MVS_DISK_FLOOR_MB` | 磁盘余量底线，低于它不启动命令（默认 1024） |
| `MVS_RESTORE_DELETED` | 回滚时是否恢复被删文件 |
| `MVS_KOFFI` | 指定 koffi 原生模块路径（FFI 用） |

## 工具清单

| 工具 | 作用 |
|---|---|
| `read_file` | 读文件（支持行范围；超长会分片） |
| `write_file` / `create_file` | 写、创建 |
| `edit` | 局部替换（按原文匹配，不整文件重写） |
| `delete_file` / `delete_paths` / `move_path` | 删、批量删、移动（带联结检查） |
| `glob` / `grep` | 找文件、搜内容 |
| `run_command` | 执行命令（默认进沙箱；`background: true` 起后台作业） |
| `list_jobs` / `job_output` / `kill_job` | 后台作业的查看与终止 |
| `web_search` / `web_fetch` | 联网检索与抓取（受网络策略管） |
| `search_skills` / `use_skill` | 技能检索与调用 |
| `spawn_agent` | 开子 Agent（买的是**上下文隔离**，不是并行 —— 本地引擎只有一个槽位） |

## 状态目录里有什么

```
~/.mvs-agent/
├─ config.json        配置
├─ state.json         工作区与会话索引
├─ sessions/          每条会话的事件日志
├─ recovery/          事务快照（可撤销的依据）
├─ jobs/              后台作业的日志
├─ review-state.json  输出审核的累积状态（切片、窗口）
├─ taint.json         被打码过的路径
└─ reveal-code.json   一次性可见性代码（用后即焚）
```

`npm run maintain` 会按 TTL 清理过期项。删掉整个目录等价于「恢复出厂」—— 会话与历史都会丢，配置也会没。
