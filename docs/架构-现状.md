# 架构现状：现在这套东西是怎么搭的

> 这份文档描述**当前**的架构。旧架构（DSH 复刻页 + 垫片 + 品牌页）已在 2026-10-18 连同生成器一起删掉，
> 描述它的三份文档在 `docs/` 里仍留着，但只应**当历史读** —— 见文末。
>
> 写在界面重做完成、缓存命中率与生成参数接入之后。每条都指到代码，不是印象。

---

## 一、一句话

**一个本机 Agent 内核**（`src/`，零运行时依赖，Node 直接跑 TypeScript），
**加一个自己写的 React 界面**（`ui/` → `web/`，由守护进程直接服务）。

没有第二个服务器。守护进程把界面当静态文件发出去，同一进程上开着 HTTP 与 WebSocket。

---

## 二、五层

```
ui/                 界面：React + TSX，esbuild 打包到 web/
  ├ client.ts           传输层：只负责"怎么和守护进程说话"
  ├ useSession.ts       会话状态机：投影是真相、增量只是提示
  ├ useIndex.ts         工作区/会话列表（/state）
  ├ settings.ts         界面设置（localStorage，不碰 daemon）
  ├ markdown.tsx / math.ts / App.tsx / Settings.tsx
  └ styles.css

web/                产物目录（守护进程服务的就是它）
  ├ index.html          由 ui/index.html 生成，引用**带内容哈希**的文件名
  ├ app-<hash>.js/.css  内容一变名字就变
  └ KaTeX_*.woff2       数学字体（只放 woff2）

src/host/           宿主层
  ├ server.ts           HTTP + WebSocket；四个协议面都在这里
  ├ runtime.ts          工作区、会话、作业、状态存储
  ├ session.ts          会话状态机（回合、步骤、工具、审批、上下文）
  └ directory-picker / picker / directory-browse    路径选择（DSH 那套）

src/model/          模型层：请求进，事件流出（providers 无关）
src/policy/         策略：模式、风险、只读证明、抗疲劳熔断
src/recovery/       恢复：动作前后整树快照
src/config/         配置：文件 → 归一化 → 解析（唯一写入口是用户动作）
src/protocol/       契约：命令与事件的类型定义
```

## 三、四个协议面（界面只用这四样）

| 面 | 作用 | 关键约定 |
|---|---|---|
| `GET /state` | 工作区与会话列表、配置（密钥只给掩码）、上下文窗口及其**出处** | 稳定，可缓存 |
| `GET /projection?sessionId=` | 一个会话的**完整投影** | **唯一真相**：落盘内容只从它来 |
| `POST /command` | 命令（发消息、中止、建/改/删会话、改模式…） | 返回值必须当真（见不变量 2） |
| `WS /ws` | 事件推送（**只是提示**） | 订阅**按连接**记：连上要先 `watch` |

### 流式渲染为什么这么设计

```
messages  永远由 /projection 重建        ← 真相
live      只被 model_*_delta 追加        ← 提示
```

提示丢了、重了、乱了都不影响正确性 —— 下一次重建就纠正回来。
旧那套把流式做成独立通道、自带计数器、还要和落盘对账；两套数一错开就**静默重建**，
我们花了两天才定位。现在的规则简单到不需要对账。

### 已知的一个前提（不是缺陷，但要知道）

那条"增量只推给声明在看的连接"的闸门，依赖客户端**连上就 watch**
（`ui/client.ts` 的 `connectSession` 在 `open` 里第一件事就是发它）。
根治办法是**让动作与流走同一条通道**（把 `user_message` 也放到 WS 上，
服务端收到就顺手登记订阅）—— **这一条还没做**，见文末欠账。

## 四、七条不变量（改代码前先看这里）

1. **投影是真相，增量只是提示。** 任何"界面自己记一份"的状态最终都会漂 ——
   权限模式、上下文用量、缓存命中都从投影来。
2. **命令的返回值要当真，也要如实回报。** `user_message` 刻意不等待（一轮可能跑几分钟），
   所以它**必须同步检查前置条件**并回 `ok:false` —— 否则界面显示"发送成功"却什么都不发生。
3. **阻塞态必须配出口。** 目前三个：等批准（`approve`）、结果未知（`acknowledge_interrupted`）、
   审批熔断（`reset_fatigue`）。**只加闸门不加门**，用户就会被锁在门外，而界面上看不到原因。
4. **失败不许静默。** 取不到、算不出、端点不给字段 —— 显示 `—` 并说明为什么，
   而不是显示 0 或干脆不显示（"不知道"和"没命中"是两件事）。
5. **产物文件名带内容哈希。** 这不是审美：固定名字的资源会被浏览器缓存钉住，
   服务端改了七八版而浏览器一版没取，**而所有开发侧验证都不经过浏览器缓存** ——
   于是看起来一切正常。哈希从构造上消掉这件事。
6. **后端配置 ≠ 界面设置。** 界面设置写 `localStorage`（只影响这台浏览器）；
   模型、温度、输出上限、权限默认值属于 daemon，写 `~/.mvs-agent/config.json`，
   **只能因为用户明确的一次动作而改变**（见 `现状-全貌.md` 第一节那条硬规则）。
   ⚠️ 密钥的掩码**绝不能回写**。
7. **不拿上限掩盖模型重复。** 模型重复输出是模型层的事实；`maxTokens` 默认不设，
   界面不主动加。要设是给人自己用的。

## 五、怎么跑

```bash
npm run serve            # 守护进程（界面在 http://127.0.0.1:3080/）
npm run ui:build         # 改完 ui/ 之后构建到 web/（产物名带哈希）
npm run ui:build:dev     # 同上，但用 React **开发版**（换来可读的 hooks/key 警告）
npm run ui:typecheck     # 界面类型检查
npm run typecheck        # 内核类型检查
npm test                 # 测试（见下面的已知缺陷）
```

⚠️ **界面默认按生产版构建**（2026-10-05 改的，原来写死开发版）：

| | 开发版 | 生产版（默认） |
|---|---|---|
| JS | 2,242 KB | **773 KB** |
| CSS | 49 KB | **41 KB** |
| React 警告 | 有（可读） | 只剩 `Minified React error #xxx` + 链接 |

sourcemap 一直开着，所以**生产版的栈轨迹照样指到源码行**；丢掉的只是 React
自己那几句警告。要那些警告时用 `npm run ui:build:dev`。

**生成参数**（后端配置，改完要重启 daemon；会话构造时读一次）：

```json
{ "model": { "temperature": 0.5, "maxTokens": 8192 } }
```

## 六、已知缺陷（都还没修）

| 缺陷 | 影响 |
|---|---|
| **测试不隔离状态目录** | 夹具把恢复层建到真实的 `~/.mvs-agent/recovery`，于是（一）在 `workspace-write` 受限策略下**整片失败**，（二）跑起来时会动真实数据 |
| **`test/` 下有约 250 个 `.tmp-*` 残留** | 历次测试跑剩的夹具，很多含目录联结 —— **不能用 `Remove-Item -Recurse` 清**（有删到链接目标的风险） |
| ~~`/brand` 是"公开静态页"，但页面已归档~~ | **已修好（2026-10-18）**：页面与生成器都删了，公开白名单清空，测试改成断言"没有任何路径免鉴权" |
| **命令没上 WebSocket** | 见第三节那个前提 |
| **并发：单槽位引擎** | 另一个会话在生成时，你这条会排队；界面给了提示，但没有真正的排队语义 |
