## 硬规则：**MVS Agent 的配置不得被隐式改写**

> 用户原话：「MVS Agent 的配置又被改了，**不能改，不能改**」。
> 这条不是风格偏好，是**数据完整性**要求 —— 见下面每条"真实发生过"。

**规则**：`~/.mvs-agent/config.json` 只能因为**用户明确的一次配置动作**而改变。
任何「顺手写回」「同步一下」「为了让界面好看」都**不允许**碰它。

### 唯三写入口（都汇聚到 `ConfigStore.save`）

| 入口 | 触发者 |
|---|---|
| `POST /model-config` → `Runtime.updateModel` | 垫片的 `settings/mutate`（设置页保存）、`credentials/set\|unset`（密钥） |
| `POST /command {type:'set_config'}` → `Runtime.applyConfig` | 目前**无人发送**（曾被我误用） |
| `mvs config` 命令行 → `store.save` | 用户手动执行（另一进程） |

**守护进程自己从不写配置**：启动、本地模型启动、窗口探测走的都是私有的
`#applyConfig`（只在内存生效、不落盘）。实测：启动 11 秒内 `[config] 写入` 0 次。

### 四条**绝对不允许**发生（每条都真实发生过）

1. **掩码落盘 → 密钥不可恢复。** 出站把密钥换成 `••••`，界面回传时它被当成真密钥
   存了回去：`providers.deepseek.apiKey` 长度从 35 变成 4
   → 修复：`ConfigStore.save` 对**每个** `providers.<route>.apiKey` 还原（不只 `model` 段）
2. **`activeProvider` 悬空被丢。** 写 `'mvs'`（当时不在 `providers` 里）→ 规范化时被当
   悬空引用丢掉 → **内存说 mvs、磁盘没这个键**
   → 修复：`mvs` 落成真实供应商条目；且测试钉住"写了必须在磁盘上"
3. **一次操作改所有会话。** 在**会话里**选模型被实现成"写全局配置"
   → 修复：会话级 `select_model`（`Session.selectModel`），**不碰配置文件**（实测 0 次写入）
4. **改 A 改到 B / 改到全局默认。** 合成的「MVS Agent」卡片背后是 `model` 段
   （**所有会话的兜底**），用户以为在改"一个供应商"
   → 修复：`providers.mvs` 成为普通条目；`model` 段仅作无会话级选择时的兜底

### 出问题怎么定位：**来源记录**

`ConfigStore.save` 每次写入都打一行，含**变化的键路径** + **调用栈**，密钥**只报长度**：

```
[config] 写入 config.json：providers.deepseek.model: "qwen3.6" → "deepseek-flash"
         调用方：at async Runtime.applyConfig (runtime.ts:460) ← Runtime.updateModel (runtime.ts:385)
                 ← #handleRequest (server.ts:912)
```

于是只有两种确定结论：**日志里有** → 栈里是哪个调用方；**文件变了但日志里没有** →
外部写入者（手改、别的进程），且精确到秒。

### 怎么防回归

- **守护进程侧**：`test/config.test.ts` 里的钉住测试（掩码还原、`mvs` 落盘、会话级选择不改配置）
- **垫片侧**：没有测试框架，用**运行期绊线**把静默失效变成明确报错
  （`结算编号对不上`、`投影帧号没有递增`、`选完之后投影没跟着变`、`未实现的 RPC`）

## 零、这是什么，怎么跑

一个**零运行时依赖**的本地 Agent 内核（TypeScript，Node 直接跑 `.ts`，不需要构建步骤）。

```bash
npm run serve         # 守护进程，默认 3080
npm run chat          # 裸对话 REPL（只连模型，不带工具）
npm test              # 359 条测试

```

**60 个源文件 / 578 KB / 9 个模块；359 条测试 / 19 个文件；121 个 `.mjs` + 38 个 `.js` 工具脚本。**

**当前进程状态（实测）：** 守护进程 `:3092` HTTP 200 · 根页面 200 · `llama-server` `:8080` 200

## 二、能用的（有验证证据）

### 1. 模型层 —— 能用

- `openai-compatible.ts` 一个协议实现，SSE 流式解析
- 思考内容（`reasoning_content`）→ 协议层 `assistant_message.reasoning` → 界面折叠成「思考」块
- **实测**：`--reasoning on` 下模型吐 2500–3500 字符思考；32B 模型 128K 上下文 45 tok/s
- `--reasoning` 默认 `on`（用户要求）

### 2. 工具层 —— 能用，11+2 个

```
read_file · write_file · create_file · delete_file
glob · grep · edit
run_command · list_jobs · job_output · kill_job
web_fetch · web_search        ← 本轮新增
```

- **实测**：agent 用 `grep → read_file → edit → read_file` 正确改了 3 处
- `edit` 在 `oldString` 有多个匹配时报 `ambiguous`，除非 `replaceAll`
- `grep` / `glob` 纯 Node 实现（不用 `rg` / `findstr`）—— 因为那些**每台机器行为不一样**，而工具输出形状必须是确定的
- `web_fetch` 无需密钥，**实测**抓 `nodejs.org` 出 5686 字符正常正文
- `file://` 被拒（否则是绕过路径围栏读任意文件的后门）

### 3. 权限层 —— 能用，但有假承诺

三种模式 `read-only` / `workspace-write` / `full-access`，判定 `allow` / `deny` / `ask`。

`read-only.ts` 用「程序 + 子命令 + 参数形状」证明只读，并拒绝任何 shell 元字符。**这块是扎实的。**

**但它的文件头注释承诺了一个不存在的沙箱**（原文"沙箱该管这件事，而这个模块不管"）。真相是：**`run_command` 只围栏 `cwd`，不围栏命令能碰到什么。**

### 4. 恢复层 —— 能用

13 处工具故障点写入 recovery，事务化。22 条测试。

### 5. 会话持久化 —— 能用

事件流落盘 + checkpoint，崩溃后能恢复。`session/#emit` → store → 重放。

### 6. 前端 —— DSH 自己的，不是我们写的

`web/` 是**真实的 DSH 前端**（React，73 个客户端插件），由 `build-dsh-replica.mjs` 从本机安装里复制 + 品牌替换。我们的 `tools/replica-shim.js`（约 3700 行）把 DSH 的 `/api/*` RPC 翻译到我们守护进程的 `/state` + `/command`。

**好处：** UI 完全是 DSH 的组件在渲染，「和 DSH 对齐」是结构上成立的。
**代价：** 翻译层要说清 DSH 要什么形状，而这层是我们写的。

## 三、半成品 / 此刻是坏的

### 1. 配置层正在返工（**这是当前唯一挡着构建的东西**）

```
✖ src/config/resolve.ts(354,5)  Type '(string | ModelDefinition)[]' is not assignable to 'string[]'
✖ src/config/resolve.ts(356,34) No overload matches

测试 359 / 通过 356 / 失败 2
  ✖ providers：models 去重、丢弃空串和非字符串
  ✖ ★ POST /model-config：`models` 是可选模型目录，空数组是有意义的
```

原因：`ModelConfig.models` 从 `string[]` 改成了 `ModelDefinition[]`（DSH 的形状），`resolve.ts` 里摊平那段没跟上。

### 2. 供应商 / 模型 —— 数据层通了，其余半截

**已验过（改形状之前）**：界面上建一个供应商之后

```
模型页正文: MVS Agent 自定义 编辑 · probeadd 自定义 编辑 · 添加模型提供商
编辑按钮个数: 2
```

**已修的两个真 bug：**

| bug | 后果 |
|---|---|
| `settings/mutate` 对不认识的路径**静默跳过**再回 `ok` | 对话框关了、没报错、供应商不见了 |
| `/state` 只暴露当前生效那一份 | 写入通、读不出来，**比上一条隐蔽** |

**没做的：**

- **`deriveKeyRef` 没实现** —— DSH 的凭据引用名是从 route 派生的（`<ROUTE>_API_KEY`）
- **`credentials/set` 里 `void key`** —— 引用名被丢掉，第二个供应商的密钥会写进 `model.apiKey`
- **`api` 字段收下就丢** —— 当时理由是"我们只会说 OpenAI 兼容那种"，**那是个错的取舍**：用户选了协议、我们丢了、按默认发
- **`profile` 不跟着供应商切** —— `windowTokens` / `includeUsage` 还按旧 profile 走

### 3. 「本地模型」设置分区 —— 是我手写的

`plugins-src/mvs-local-model/client.js`（约 300 行）用 `react.createElement` 手搓。**这是这个项目里唯一我们自己写的显示代码**，其余都是 DSH 的组件。

## 五、有问题 / 有坑的

### 1. DeepSeek 从界面配了用不了 —— 实测确诊

用户配置里是 `baseUrl = "http://api.deepseek.com"`。拿真 key 打三次：

| URL | 结果 |
|---|---|
| `http://api.deepseek.com/chat/completions` | **401** |
| `http://api.deepseek.com/v1/chat/completions` | **401** |
| `https://api.deepseek.com/v1/chat/completions` | **200** |

**密钥和模型名都对，唯一问题是 `http://`。DeepSeek 在 http 上直接 401，不重定向。**

而 DSH 的「规范化」只是 `trim()` —— **它也会接受 `http://api.deepseek.com`，也一样 401。这条两边都有，不是没抄。**

### 2. 沙箱：事实与承诺不符

**事实：**

| 路径 | 能否到工作区外 |
|---|---|
| `read_file` | **不能**（`outside_root`） |
| **`run_command`** | **能** —— 实测 `type C:\Users\…\.mvs-agent\config.json` 把整个配置打出来了 |
| **网络** | **能** —— 实测 HTTP 200 |

**「读自己的密钥 → 发出去」是一条完整可达的路径，三个命令的事。**

一旦指向远端 API，模型输出就是不受信任输入，提示注入是活的。而读密钥和走网络**都没有围栏**。

### 3. `interactive` 恒为 `true`，而没有审批 UI

`policy.ts` 的规则是「无人可应答 → 立即拒绝，而不是假装问过了」。但守护进程路径上 `interactive` 默认 `true`，于是 `ask` 判定会去等一个永远不来的答复。

### 4. `tools/replica-shim.js` 改了不等于生效

必须同步到 `web/replica-shim.js`。有 `check-shim-sync.mjs` 能查，**但没有自动同步**。本轮踩了一次：改完去界面看什么变化都没有。

### 5. `probe-eval.mjs` 的 `--wait` 坏了

`--wait .tPVXea_listArea` 一直报「没拿到结果」，去掉改 `--delay` 就正常，而那个选择器确实在 DOM 里。

### 6. 121 个工具脚本没有生命周期

`tools/` 里 121 个 `.mjs` + 38 个 `.js`，大部分是一次性探针。这一轮我删了 12 个，**但还有一大批是死的**。

### 7. 恢复备份文件没清理

`~/.mvs-agent/` 里躺着 2 个 `state.json.before-restore-*`（9 KB + 11 KB）。

## 六、我的失误模式（这一轮五次）

**同一个形状：结论建立在没验过的前提上。**

| 我说的 | 实际 |
|---|---|
| `run_command` 读不到密钥 | 我的命令双重 shell 包裹了，重写就读到了 |

**五次里三次是我自己的工具错，而现象看起来像产品有问题。**

另一次：写 `test/web-api.test.ts` 前没先找 `test/` —— 那里已经有一个 299 行的 `web-api.test.mjs` 覆盖同样内容，用 `.mjs` 根本不用折腾 tsconfig。

**还有一次是承诺与事实不符**：`read-only.ts` 的文件头把沙箱的职责推给了一个不存在的沙箱。那不是 bug，是一句会误导下一个人的话。
