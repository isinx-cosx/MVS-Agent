# 后端缺陷清单（代码扫描版）

> 这份是**按代码扫出来的**缺陷清单，和 [挡不住清单](挡不住清单.md) 分工不同：
>
> - **挡不住清单** 回答"外部能突破什么"
> - **这份** 回答"我们自己哪里写得不够好，怎么改、先改哪个"
>
> 每条都有 `文件:行` 证据，不给"感觉上应该加固一下"这种条目。

## 优先级定义

| 级别 | 含义 | 处理期限 |
|---|---|---|
| **P0** | 可绕过 / 直接造成检测失效 | 本波必须做 |
| **P1** | 明显缺口，有实际攻击或误用路径 | 下一波 |
| **P2** | 加固与体验，缺了不影响正确性 | 排期 |
| **P3** | 已知并接受，记录在案 | 不做，只留说明 |

## 一、沙箱层（`tools/sandbox-*.mjs`、`src/sandbox/`、`src/tools/command-tool.ts`）

| 编号 | 缺陷 | 证据 | 优先级 | 解决方案 |
|---|---|---|---|---|
| S1 | **写字节只在 50 ms 轮询里检查**：一次突发写在窗口内完成，`TerminateJobObject` 来不及 | `tools/sandbox-net-run.mjs:354`（`WaitForSingleObject(hProcess, 50)`）、`:381`（事后才置 `exceededWriteBytes`） | **P1** | Job Object 没有磁盘配额，靠轮询永远有窗口。正解是**NTFS 磁盘配额**：给 AppContainer 的 SID 设 hard quota，超了由文件系统拒绝；轮询降为 10 ms 作为补充。做不到配额时，至少把写入目录换成**临时 VHD**，容量即上限 |
| S2 | **后台作业完全不走沙箱** | `src/tools/command-tool.ts:196`（只发警告）、`:304-310`（`jobs.start` 直接 spawn） | **P1** | 作业要活过命令，但可以"活在另一个常驻 worker 里"：daemon 侧维护一个沙箱 worker 进程池，作业进程作为 worker 的子孙（job object 不带 `KILL_ON_JOB_CLOSE`），worker 常驻不随命令退出 |
| S3 | **`%TEMP%` 被授予 `M`**，写范围超出"只工作区" | `src/cli/sandbox-grant.ts:44`（`{ path: tmpdir(), rights: 'M' }`） | **P2** | 改成按会话建 `%TEMP%\mvs-<sessionId>` 并只授权它，命令结束时删除；工具需要的临时文件走 `TMPDIR` 重定向 |
| S4 | **授权用固定 SID `S-1-15-2-1`**（所有 AppContainer 通用），且 ACE 长期留在工作区 | `src/sandbox/appcontainer.ts`（`APP_CONTAINER_SID`）、`src/cli/sandbox-grant.ts:42-45` | **P2** | 为 MVS 建专属 profile 并 `DeriveAppContainerSidFromAppContainerName` 得到自有 SID，授权只给这个 SID；`--remove` 纳入 `npm run sandbox:reset` |
| ~~S5~~ | ~~**只改 ADS、主数据流不变时不产生事务**~~ **已修**：快照记 `streamCount`，diff 比较它 |，因此 ADS 枚举根本不会跑到 | `src/recovery/guard.ts:252`（只枚举 `changes.added/modified`） | **P1** | 快照阶段对每个文件多记一项"流数量 + 总字节"（一次 `FindFirstStreamW`），把这一项纳入 diff 判据；或在命令前后对**工作区做流扫描**（只扫 mtime 变化的目录） |
| S6 | **ADS 枚举有静默截断**：50 文件 / 16 流 | `src/recovery/guard.ts:252`、`src/recovery/ads.ts`（`MAX_STREAMS = 16`） | **P2** | 截断时在结果里明确写 `truncated: true` 与"还有 N 个文件没查"；判据改成字节预算而不是条数 |
| S7 | **每条命令都跑 ADS 枚举**（最多 50 次 FFI） | `src/recovery/guard.ts:252-258` | **P2** | 只在 `run_command`（能写文件的工具）后做，文件读/搜类工具跳过 |
| S8 | **沙箱坏掉时只能整机 `MVS_SANDBOX=off`**，等于放弃全部隔离 | `src/tools/command-tool.ts:119-121` | **P2** | 分级降级：`off` → `job-only`（仍有进程数/内存/CPU/写字节上限，只是没有 AppContainer 断网与写隔离）。让用户"少挡一点"而不是"一点不挡" |
| S9 | 句柄隔离断言是**单向**的（没有正向对照） | `tools/handle-list-probe.mjs` 文件头 | **P3** | 不接受为测试引入不安全开关；结论限定为"`EBADF` 证明拿不到" |
| S10 | 非 Windows 平台完全没有沙箱层 | `src/sandbox/` 只有 Windows 实现 | **P2** | Linux：user namespace + seccomp + cgroup；macOS：`sandbox-exec` profile。若产品不跨平台，这条写进 README 声明 |

## 二、审核层（`src/guard/`、`src/host/session.ts`）

| 编号 | 缺陷 | 证据 | 优先级 | 解决方案 |
|---|---|---|---|---|
| ~~R1~~ | ~~**分片读取计数只在内存里**~~ **已修（第一波）**：重启 daemon 就清零，读 4 次 → 重启 → 再读 4 次，永远到不了阈值 | `src/host/session.ts:249`（`#readSlices = new Map(...)`） | **P0** | 落盘到 `.mvs/review-state.json`（与 `taint.json` 同一套 `TaintStore` 风格）：`{ path: { calls, covered, total, updatedAt } }`，加载时合并 |
| ~~R2~~ | ~~**分段窗口只在内存里**~~ **已修（第二波）**：同上，重启后第 2、3 段无法与之前的段拼接 | `src/host/session.ts:240`（`#chunkWindows`） | **P1** | 与 R1 同一个状态文件，按来源存最近 N 段（带时间戳，超过 24 h 丢弃） |
| R3 | **解码深度固定 3 层**，第 4 层起放弃 | `src/guard/scan.ts`（`redactEncodedDeep(text, maxDepth = 3)`） | **P2** | 不改深度（再深人也不可读），但检测到"解出仍是编码"时给一条**提示**而不是静默放过 |
| R4 | **分段窗口只 8 段**，切 9 段以上拼不起来 | `src/guard/scan.ts:423`（`CHUNK_WINDOW = 8`） | **P2** | 提到 16 段 + 时间窗；组合仍只试连续后缀，避免组合爆炸 |
| ~~R5~~ | ~~**分片阈值偏松**~~ **已修（第二波）**（≥5 次且覆盖 >50%）：读 4 次各 1/4 完全不触发 | `src/host/session.ts:1524` | **P1** | 三条判据任一命中即降级：覆盖 ≥30% / 次数 ≥3 且平均切片 <10 行 / 同一文件被"不连续读取"≥3 次 |
| ~~R6~~ | ~~**跨文件没有总量预算**~~ **已修（第二波）**：逐个文件都正常，合起来捞了 200 个文件 | 无对应代码（`#readSlices` 按路径独立） | **P1** | 会话级预算：每轮累计读取行数上限（例如 5000 行），超限后本轮剩余读取一律只给元信息，并在事件里说明 |
| R7 | **敏感路径识别靠名单**：名单外的敏感文件只能靠内容命中 | `src/host/session.ts:1442`、`:1550`（`isSensitivePath`） | **P2** | 名单只做"快速通道"；真正的判据应是内容（已实现）。补一条：一旦某路径**内容命中过密钥**，永久进"只给元信息"集合（现在靠 taint，语义对但命名是 taint，容易误解） |
| R8 | **`SELF_AUTHORED` 免审集合缺一条"防误加"的测试**：当前只含 6 个写类工具（正确），但以后加工具时没人拦 | `src/guard/review.ts:163-173` | **P2** | 加断言：免审集合里的每个工具，喂"外部内容"必须不产生输出；不在集合里的工具必须被扫。这样新工具加错会立刻红 |
| R9 | **`revealSensitive` 只在交互模式可用**：CLI 用户等于没有出口 | `src/host/session.ts:1471` | **P2** | 加一个一次性确认码：CLI 里先 `npm run reveal:code` 拿 6 位码，工具调用时带上它（一次性、5 分钟过期、进事件流） |
| R10 | **没有审核统计**：扣了多少、什么类型，只能翻事件流 | `src/host/session.ts`（`#reviewOutput` 里只有单次 `parts`） | **P2** | 每轮结束发一条 `review_stats` 事件 `{ secrets, pii, encoded, fragments, chunked, withheld }`，UI 与 CLI 都能用 |

## 这份文档怎么保持有效

- 每条都带 `文件:行`；**改完代码要同步改这里**，行号对不上就是过期
- 新增缺陷先归到某一层，不要开"杂项"
- 优先级只按"会不会让检测失效"排，不按工作量排
