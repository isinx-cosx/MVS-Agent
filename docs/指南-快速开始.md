# 快速开始

这篇讲「从零到能用」：装什么、怎么起、第一句话怎么发。其余细节各有专篇（见文末）。

---

## 它是什么

MVS Agent 是一个**跑在你本机的 agent 内核**。你给它一个工作区目录，它能读文件、改文件、执行命令、查资料、开子 Agent；每一次动作都留痕，每一次改动都能撤销。

和「聊天机器人」的区别在于：它**真的动手**，所以这一整套设计里有一半是「怎么让它动手而不越界」。

---

## 需要什么

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11（沙箱走 AppContainer；其它平台可运行但沙箱能力有限，见 `docs/sandbox-platform-matrix.md`） |
| Node.js | 22 以上（本仓库用 Node 的类型剥离，源码里的 `.ts` 直接跑，不需要编译） |
| 模型 | 任意 OpenAI 兼容端点：本机 llama.cpp / Ollama，或云上的 API |

界面是 React，构建产物在 `web/`，已经在仓库里 —— **不改界面就不需要构建**。

---

## 第一次启动

```powershell
# 1) 起服务（开发阶段可以不带令牌；默认是要求令牌的）
node src/cli/serve.ts --port 3080 --no-token

# 2) 浏览器打开
#    http://127.0.0.1:3080/
```

启动信息会打印模型、上下文窗口、工作区数与端点，例如：

```
模型      qwen3.6  @ http://127.0.0.1:8080/v1 (无 key)
默认模式  workspace-write
上下文    窗口 32768 · 可用预算 28672
界面      http://127.0.0.1:3080/
```

## 配置模型

第一次用会看到「未配置模型」—— 这是**故意的**。没配就是没配，不会偷偷连本机 Ollama 让你以为连上了。

三种方式任选：

```powershell
# A. 用命名预设
node src/cli/serve.ts --profile ollama        # 本机 Ollama
node src/cli/serve.ts --profile llama         # 本机 llama.cpp
node src/cli/serve.ts --profile deepseek      # 云上 DeepSeek（要 DEEPSEEK_API_KEY）

# B. 直接给端点与模型名
node src/cli/serve.ts --base-url http://127.0.0.1:8080/v1 --model qwen3.6

# C. 写进配置文件（界面「设置」页也能改）
node src/cli/config.ts set model.baseUrl http://127.0.0.1:8080/v1
node src/cli/config.ts set model.model qwen3.6
```

密钥的读取顺序是：命令行 > 环境变量 > 配置文件里的 `apiKeyEnv` 指向的变量 > 配置文件里的明文。**明文密钥永远不会出现在界面里**，界面只显示打码后的尾巴。

## 第一次对话

1. 左侧选一个工作区（或点「打开工作区」加一个目录）
2. 输入框打字，`Enter` 发送，`Shift+Enter` 换行
3. 回答会带上「执行过程」：它想了什么、调了哪个工具、花了多久

发出第一条消息之后，这条对话才算**真的创建**；在那之前只是一块空白等你说第一句。

---

## 权限模式

输入框下面的「权限 · …」是**这个会话**的权限上限：

| 模式 | 能做什么 |
|---|---|
| `只读` | 只能看：任何写入与命令都会被拒绝 |
| `可改工作区` | 只能改工作区里的文件；工作区外一律拒绝（默认） |
| `完全放行` | 不再限制范围 —— 等于把这台机器的权限交给模型 |

改的是当前会话，不是全局配置。想知道某次拦截为什么发生，看对话里的工具调用与顶部栏的「已拦下」。

## 沙箱（Windows）

默认开启，命令在 AppContainer 里跑：断网、只能写工作区、限进程数与内存。

新机器第一次建议跑一次授权（**管理员** PowerShell）：

```powershell
npm run sandbox:grant -- .
```

它做四件事：给工作区可写、给祖先链「穿过」权限、给 `C:\Program Files\nodejs` 只读可执行、给 npm 目录只读。

`git` / `npm` 这类开发工具按设计**跑在沙箱外**（MSYS 与盘根读属性在容器里起不来），结果里会标 `sandbox: off-tool` 并附原因 —— 不静默放宽。

不想要沙箱：启动前设 `MVS_SANDBOX=off`。命令行工具（`run_command`）会因此不受范围限制。

---

## 改界面之后

```powershell
npm run ui:build      # 生产版
npm run ui:build:dev  # 带 React 可读警告
```

服务端每次请求都从磁盘读 `web/`，所以构建完刷新浏览器即可 —— **不构建就是旧产物**。
