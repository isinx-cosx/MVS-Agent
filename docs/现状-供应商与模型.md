## 四、完全没做的

### 1. `deriveKeyRef` —— DSH 有，我没有

DSH 的凭据引用名是**从 route 派生**的，不是用户填的：

```js
function deriveKeyRef(provider) {
  return `${provider.toUpperCase().replace(/[^A-Z0-9]+/g, '_')}_API_KEY`;
}
```

**没做。** 所以「profile 里存引用名、凭据单独存」这条链是断的。

### 2. `credentials/set` 把 key 丢掉了

```js
const key = arg('ref', 0)
const value = arg('value', 1)
void key          // ← 引用名被丢掉
```

**后果**：给第二个供应商填的密钥会写进 `model.apiKey`（当前生效那个），而不是 `providers.<route>.apiKey`。

**这是「照抄 DSH 逻辑」里最容易漏掉的一环** —— DSH 是两步：先 `writeSettings`（profile，含 `apiKeyEnv` 引用名），再 `storeCredential(keyRef, value)`。

### 3. `api` 字段还是收下就丢

```js
if (leaf === 'api') continue   // 只接受、不保存
```

我当时写的理由是「我们的守护进程只会说 OpenAI 兼容的那一种」。**那是个错的取舍**：用户选了协议、我们丢了、然后按默认的发 —— 现象就是「这个供应商填了没用」。

### 4. `profile` 不跟着供应商切

配置里 `profile` 是一个全局值（`llama` / `deepseek` / `ollama` / `fake`）。切 `activeProvider` 时它不变，于是 `windowTokens`、`includeUsage` 这些还按旧 profile 走。

### 5. 「显示也抄」这件事

- **设置页本身是 DSH 的**（`dsh-client-ui-settings-models`），这部分没问题
- **但 `plugins-src/mvs-local-model/client.js`（「本地模型」那个分区）是我自己手写的 React** —— 那是我在写显示
- DSH 那一整套校验显示（`customRouteInvalid` / `routeTaken` / `baseUrlInvalid` / `keyFailure` / `modelFailure`）我**不需要写**，只要把数据喂对，DSH 的组件会渲染

## 五、有问题 / 有坑的

### 1. DeepSeek 从界面配了用不了 —— 实测确诊

用户配置里现在是：

```
profile       = "llama"
model.baseUrl = "http://api.deepseek.com"    ← http，且缺 /v1
model.model   = "deepseek-flash"
```

我拿真 key 打了三次：

| URL | 结果 |
|---|---|
| `http://api.deepseek.com/chat/completions` | **401** Authentication Fails |
| `http://api.deepseek.com/v1/chat/completions` | **401** Authentication Fails |
| `https://api.deepseek.com/v1/chat/completions` | **200** 模型回话了 |

**密钥和模型名都是对的，唯一的问题是 `http://`。DeepSeek 在 http 上直接 401，不重定向。**

**而 DSH 的「规范化」只是 `trim()`：**

```js
const normalizedBaseURL = baseURL.trim();
const baseUrlInvalid = baseURL.length > 0 && !isHttpUrl(normalizedBaseURL);
//                                          ↑ 只校验必须是 http/https 开头
```

**所以 DSH 也会接受 `http://api.deepseek.com`，也会一样 401。** 这条不是"没抄 DSH"，是**两边都有这个洞**。

### 2. `tools/replica-shim.js` 改了不等于生效

**必须同步到 `web/replica-shim.js`。** 这一轮我踩了一次：改完源码去界面上看，什么变化都没有 —— 因为服务的是旧的。

有 `tools/check-shim-sync.mjs` 能查，但**没有自动同步**。

### 3. `probe-eval.mjs` 的 `--wait` 坏了

`--wait .tPVXea_listArea` 一直报「没拿到结果 —— 页面可能没加载」，但**去掉 `--wait` 改用 `--delay` 就正常**，而那个选择器确实在 DOM 里。

我在这上面绕了好几轮才发现不是我的表达式的问题。
